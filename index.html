How does this work?

Why encode at all? A receiver watching a lamp has no ruler. If the lamp stays off for a while, it can’t tell how many 0s went by. An encoding adds structure so the receiver can keep time and stay in step with the sender.

Level. The simplest scheme: on means 1, off means 0. A long run of 1s or 0s has no changes, so counting the bits is guesswork.

Manchester. Each bit is split into two halves, and the lamp changes in the middle of every bit. That guaranteed change works like a built-in metronome (called self-clocking). The price is speed: the lamp has to change twice as often for the same data.

8B/10B. Each 8-bit byte is swapped for a 10-bit code from a lookup table. The codes are chosen so there are never more than five identical bits in a row, and so that over time the lamp is on about as long as it is off (called DC balance). Both properties help the receiver keep time.

Reading the names. Write a byte as HGF EDCBA: the first 3 bits are HGF and the last 5 are EDCBA. The name Dx.y means x = the value of the 5 bits and y = the value of the 3 bits. Example: 01001000 is 010 and 01000, so x = 8, y = 2, and the name is D8.2. D means data. K codes are special control characters; K28.5 is a sync marker that never appears as data.

Running disparity (RD). RD is a tally: − means the stream so far has had one extra 0, and + means one extra 1. Many bytes have two possible codes, one with extra 1s and one with extra 0s. The encoder picks the one that moves RD back toward zero, which is why the same byte can look different in different places.
